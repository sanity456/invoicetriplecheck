Title
ThreeWayLineMatch - Role-Separated PO Receipt Invoice Reconciliation

Notes / Description
Built ThreeWayLineMatch, a reusable role-separated PO, receipt, and invoice workflow where validators build two semantic crosswalks and code independently checks received quantities, invoiced quantities, and unit prices. Its distinct GenLayer-native mechanism is buyer PO -> receiver attestation + supplier invoice -> dual crosswalk consensus -> deterministic discrepancy codes. Correction applied: The validator now canonicalizes the leader's actual PO-to-receipt and PO-to-invoice mappings, recomputes the crosswalk digest from those mappings, compares the full payload independently, and repeats that binding before reconciliation state is written. The full selected set was checked against both steward findings: substantive leader payloads must bind every derived digest, mask, and state field, while operational registries must be owner-scoped or safely reclaimable. No web collection. All document lines and references are public caller-attested snapshots and are not authenticated. It does not approve payment, detect fraud, validate tax, establish delivery, or replace accounting controls. GenVM lint and strict typecheck pass; 11 direct tests and 1 five-validator GLSim integration test pass. A fresh repository-specific external wallet set was used, with no workspace, other-owner, or cross-repository wallet reuse. The StudioNet workflow finalized successfully in 6 transactions. The deployed source was read back byte-for-byte, the complete deployed schema matched abi.json exactly, and mechanism-specific terminal state was read back. The current release is commit 12812fcd522fa3eba19f3c0a9b8e224178592341; contract source: https://github.com/sanity456/invoicetriplecheck/blob/12812fcd522fa3eba19f3c0a9b8e224178592341/contracts/three_way_line_match.py. The earlier deployment is superseded, is identified only in the correction manifest, and is not submission evidence.
